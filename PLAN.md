# Java Blueprints — план и роли (Axenix, 48 ч)

> Кейс: веб-инструмент, который разбирает Java-монолит (~1000 строк) в граф, позволяет его исследовать и править,
> находит дефекты и Big O, улучшает код и **доказывает автотестами, что поведение сохранилось**.
> Промежуточная сдача: **25.10 08:00** — ссылка на репозиторий HR в Telegram.

## 1. Ключевые архитектурные решения

1. **Источник истины — AST, а не граф.** Код парсится JavaParser'ом в AST (с `LexicalPreservingPrinter`, чтобы
   сохранялось форматирование). Граф — *проекция* AST. Каждый узел графа хранит id AST-узла и диапазон строк.
   - Правка кода в редакторе → перепарсинг → граф перестраивается.
   - Правка на графе → **операция над AST** (изменить, вставить, удалить, переместить, обернуть в if/цикл,
     выделить метод) → код перегенерируется → граф перестраивается.
   - Так синхронизация «в обе стороны» получается бесплатно и без расхождений.
2. **Два уровня графа.**
   - *Обзор*: классы, методы, поля, граф вызовов — для монолита и декомпозиции.
   - *Блок-схема метода*: Переменная / Условие / Цикл / Вызов / Операция / Возврат / try-catch / switch — как на макете.
3. **Проверка поведения — дифференциальное тестирование.** Оригинал и изменённая версия компилируются и
   запускаются в песочнице на одинаковых входах; сравниваются stdout, stderr и код выхода.
   - Входы: заданные пользователем + сгенерированные для `Scanner`/stdin + граничные случаи.
   - Для чистых статических методов — генерируемая обвязка (harness) со случайными аргументами (fuzz).
   - Дополнительно экспорт в **JUnit golden-master тесты** (артефакт сдачи «автотесты и результат запуска»).
4. **Диагноз проверяемый.** Каждая находка: строка + узел графа + объяснение + оценка сложности + исправление +
   ожидаемый эффект. Кнопка «Применить» → авто-переписывание → дифф-тест → **замер времени до/после** на растущих входах.
5. **Оптимизации: сначала детерминированные правила, потом LLM.** Правила дают предсказуемый результат,
   LLM (Claude API) — для сложных случаев. Любое изменение проходит quality gate: сборка + дифф-тесты.

## 3. Контракты (фиксируем в первые 2 часа, дальше меняем только через PR владельца)

### 3.1 Граф — `contracts/graph.schema.json`
```jsonc
{
  "nodes": [{
    "id": "n42", "astId": "a17", "kind": "condition",   // variable|condition|loop|call|operation|return|try|switch|class|method|field
    "label": "Условие", "code": "orders == null || orders.isEmpty()",
    "range": { "file": "Main.java", "startLine": 12, "endLine": 12 },
    "parent": "m3", "findings": ["f5"]
  }],
  "edges": [{ "from": "n42", "to": "n43", "kind": "true" }] // next|true|false|loopBack|break|continue|exception|call
}
```

### 3.2 Находка — `Finding`
`{ id, rule, severity, title, explanation, file, startLine, endLine, nodeIds[], complexity: {current, after}, fix: {kind, preview}, expectedEffect }`

### 3.3 REST API (`/api`)
| Метод | Путь | Назначение |
|---|---|---|
| POST | `/projects` | загрузить .java (один или несколько файлов) |
| GET | `/projects/{id}/graph?level=overview\|method&method=…` | граф |
| PUT | `/projects/{id}/source` | правка кода → новый граф |
| POST | `/projects/{id}/graph/ops` | операция над графом → новый код + граф |
| GET | `/projects/{id}/diagnostics` | находки + метрики |
| POST | `/projects/{id}/fixes/{findingId}` | применить исправление (вернёт дифф) |
| POST | `/projects/{id}/decompose` | предложить/применить разбиение монолита |
| POST | `/projects/{id}/run` | компиляция + запуск, SSE-консоль |
| POST | `/projects/{id}/verify` | дифф-тесты оригинал vs текущая версия + бенчмарк |
| GET | `/projects/{id}/export` | zip: Java-файлы + JUnit-тесты |

### 3.4 Внутренний интерфейс анализатора
`List<Finding> analyze(CompilationUnit[] units)` — чистая функция, без HTTP и состояния.

## 4. Роли

Каждый человек = одно устройство + один агент. Агент пишет **только в своих папках**.

| # | Роль | Папки | Агент делает | Человек отвечает за |
|---|---|---|---|---|
| **1** | **Ядро: Java ↔ граф** (критический путь) | `backend/core` | парсинг, построение графа обоих уровней, операции над AST, генерация кода, сопоставление строка ↔ узел, round-trip тесты | владелец `graph.schema.json`; корректность синхронизации |
| **2** | **Анализ и оптимизация** | `backend/analysis` | правила дефектов, оценка Big O, авто-исправления, декомпозиция монолита, LLM-помощник | обоснование правил и сложности для жюри |
| **3** | **Фронтенд** | `frontend` | холст React Flow, Monaco, палитра блоков, панели «Проблемы / Консоль / Тесты», подсветка код ↔ узел | UX, сценарий демо, ручная проверка |
| **4** | **Песочница, проверка, DevOps** | `backend/api`, `backend/runner`, `docker-compose.yml`, `.github`, `corpus`, `docs` | компиляция/запуск в Docker, дифф-тесты, генерация JUnit, бенчмарк, Compose, CI, **корпус тестовых монолитов** | владелец REST API и сборки; README, описание решения, презентация |

### Детали по ролям

**1 — Ядро**
- `JavaParser` + `LexicalPreservingPrinter`; таблица `astId → Node`.
- Построитель блок-схемы: обход тела метода → узлы/рёбра (if/else, switch, for/foreach/while/do, break/continue/return, try/catch/finally, throw).
- Построитель обзора: классы, интерфейсы, методы, поля, вызовы (через SymbolSolver, с откатом на имена).
- Операции: `editNode`, `insertAfter`, `delete`, `move`, `wrapIf`, `wrapLoop`, `extractMethod`.
- **Тест round-trip на всём корпусе:** код → граф → код без правок → компилируется и вывод совпадает с оригиналом.

**2 — Анализ**
- Правила (минимум 8): вложенные циклы по одной коллекции O(n²); `list.contains/indexOf/remove` в цикле → `HashSet/HashMap`;
  конкатенация строк в цикле → `StringBuilder`; `LinkedList.get(i)` в цикле; длинный метод; глубокая вложенность /
  цикломатическая сложность; дублирование (хеш нормализованных поддеревьев); пустой `catch`; «магические» числа; god-class.
- Big O: глубина вложенности циклов × стоимость операций коллекций (таблица: `ArrayList.contains` O(n), `TreeMap.get` O(log n), …) — на метод и на фрагмент.
- Авто-исправления для топ-4 правил (детерминированные переписывания AST).
- Декомпозиция: граф зависимостей методов/полей → кластеризация (label propagation + эвристики по именам) →
  раскладка по классам `Parser / Analyzer / Optimizer / Main` → проверка через quality gate.

**3 — Фронт**
- Раскладка как на макете: дерево проекта | холст | анализ справа | код / консоль / тесты снизу.
- Клик по узлу → подсветка строк в Monaco и наоборот; маркеры находок на узлах.
- Палитра блоков (drag&drop) → `graph/ops`.
- Экран дифф-проверки: тесты N/N, «Поведение совпадает ✓», график времени до/после.
- До готовности бэкенда — моки по контрактам.

**4 — Песочница и сборка**
- Runner: временная папка → `javac -encoding UTF-8` → `java -Dfile.encoding=UTF-8` с таймаутом, лимитами, без сети; stdin подаётся из входов.
- Дифф-тестер + генератор входов + генератор JUnit golden-master.
- Бенчмарк: прогон на входах размера n, 2n, 4n → кривая времени.
- **Корпус (с первого часа):** 5–8 монолитов по ~1000 строк, покрывающих разделы 1–4 обязательного scope
  (+ бонус: record, enum, дженерики, лямбды, Stream API), с заложенными дефектами. Каждый пример проверяется вручную.
- Compose, CI (сборка + тесты + round-trip), README, `docs/` (архитектура, поддержанный scope, ограничения).

## 6. Правила совместной работы

- `main` всегда запускается; работа только в ветках `feat/<роль>-<что>`, маленькие PR раз в 1–2 часа, слияние при зелёном CI.
- Контракты в `contracts/` меняет только их владелец (граф — 1, API — 4); остальные предлагают изменение в `STATUS.md`.
- Агент в начале сессии: `git pull`, читает `CLAUDE.md`, `PLAN.md`, `STATUS.md`. В конце: обновляет `STATUS.md`, открывает PR.
- В Telegram команды — только блокеры и изменения контрактов.

## 7. Сценарий демо (финал)

1. Загружаем монолит ~1000 строк → обзорный граф классов и вызовов.
2. Открываем метод → блок-схема; клик по узлу ↔ подсветка кода.
3. Панель «Проблемы»: O(n²) в `processOrders`, дублирование, длинный метод — у каждой строка, узел, объяснение.
4. «Применить исправление» → код и граф обновились → O(n²) → O(n).
5. Правка прямо на графе (меняем условие / добавляем блок) → код синхронизировался.
6. «Декомпозировать» → `Parser / Analyzer / Optimizer / Main`.
7. «Проверить» → сборка ✓, дифф-тесты N/N ✓, «Поведение совпадает», график времени до/после.
8. Экспорт zip с Java-файлами и JUnit-тестами.

## 8. Риски и страховка

| Риск | Страховка |
|---|---|
| Синхронизация граф ↔ код ломает код | AST — источник истины; ограниченный набор операций; round-trip тест на корпусе в CI |
| Не весь обязательный scope поддержан | корпус с первого часа + матрица «конструкция → тест»; неподдерживаемое показываем узлом «код как есть», а не падаем |
| Огромный граф нечитаем | два уровня, сворачивание блоков, elkjs |
| Запуск чужого кода опасен | отдельный контейнер, таймаут, лимиты памяти, без сети |
| LLM ломает поведение | LLM только предлагает; применяется лишь после зелёного quality gate |
