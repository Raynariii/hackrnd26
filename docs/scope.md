# Поддержанный scope Java

Матрица «конструкция → граф → проверка» по обязательным разделам 1–4 кейса и бонусу (G9 в `LEAD.md`).

## Что значит «поддержано»

Каждая конструкция проходит четыре уровня. Первый, второй и четвёртый одинаковы для любого кода в примере корпуса и
проверяются автоматически на каждом примере. Поэтому в таблицах ниже показано только то, что различается:
как конструкция выглядит на графе и в каком примере она встречается.

| Уровень | Что гарантируется | Чем проверяется |
|---|---|---|
| **Разбор и печать** | Файл разбирается без ошибок, печать AST совпадает с исходником **байт-в-байт** (форматирование и комментарии сохраняются) | `CorpusRoundTripTest` (core) на каждом примере `corpus/` |
| **Граф** | Обзор (типы, члены, вызовы) и блок-схема **каждого** метода и конструктора строятся и согласованы: уникальные id, рёбра и `parent` ведут к существующим узлам | `CorpusRoundTripTest`; `raw`-узлы печатаются в лог теста |
| **Правка через граф** | Операция над блок-схемой (вставка в начало тела) проходит на каждом методе, результат снова разбирается | `CorpusRoundTripTest.checkInsertAtStart`, `GraphOperationsTest` |
| **Выполнение и поведение** | Пример компилируется в песочнице, все входы выполняются без таймаута и дважды дают одинаковый вывод, поэтому дифф-тесты `/verify` на нём не дают ложных расхождений | `CorpusSmokeTest` (runner), `corpus/check.sh` |

Анализ (`CorpusAnalysisTest`): на каждом примере считаются метрики и Big O каждого метода, у каждой находки есть
строки и узел графа.

**Конструкция, которую ядро не умеет показать отдельным блоком, не ломает разбор.** В блок-схеме она становится
узлом «Код как есть» (`raw`) со своим исходным кодом, а печать и выполнение её не трогают. На корпусе `raw`-узлов нет.

| Пример | Строк | Акцент |
|---|---|---|
| `00-hello` | 25 | smoke: ввод чисел, цикл, `Scanner` |
| `01-shop-orders` | 662 | 1–4: классы, абстрактный класс, интерфейсы, наследование, свои исключения, коллекции |
| `02-library` | 634 | 3–4: `List.of`/`Set.of`/`Map.of`, `LinkedList`, `TreeMap`/`TreeSet`, свой `Iterable`, `Optional`, `Formatter` |
| `03-bank` | 547 | 1–2: примитивы, массивы 1D/2D, `Math`, обёртки, `StandardCharsets`, `printf`, `System.exit` |

## Как читать таблицы

**На графе.** На обзоре типы — рамки (`class`/`interface`/`enum`/`record`), вложенный тип — рамка в рамке, члены
(`field`/`method`/`constructor`) — блоки внутри рамки, вызовы между методами проекта — рёбра `call`. Двойной клик
по методу открывает его блок-схему. Блоки блок-схемы: `variable`, `operation`, `call`, `condition` (Да/Нет),
`loop` (рамка с телом, возвратом и выходом), `switch`/`case`, `try`/`catch`/`finally`, `throw`, `return`,
`break`/`continue`, `raw`.

**Выражение внутри оператора** (арифметика, сравнение, приведение, тернарный оператор, лямбда, ссылка на метод,
цепочка Stream, switch-выражение) отдельной схемой не разворачивается. Оно показано кодом в блоке своего оператора,
например `Переменная: double avg = total / (double) n`.

**В корпусе:** номера примеров, где конструкция встречается и, значит, проходит все четыре уровня; «все» — 01–06
(`00-hello` — минимальный smoke). Совпадения найдены поиском по исходникам и проверены вручную. «Нет в корпусе» —
конструкция проверена тестом ядра на отдельном фрагменте.

## 1. Язык и `java.lang`

| Конструкция | На графе | В корпусе |
|---|---|---|
| Классы, вложенные `static` классы | рамка типа, вложенный — рамка в рамке | все |
| Интерфейсы | рамка `interface`, методы — блоки | 01, 03, 05 |
| `default`-методы интерфейса | блок `method` с телом и своей блок-схемой | 03 |
| Абстрактный класс, `extends`, `implements` | рамки типов; у метода без тела блок-схема из начала и конца | абстрактный класс — 01; `extends` — все; `implements` — 01–05 |
| Поля, `static`, `final`, константы | блок `field` | все |
| Методы, перегрузка | блок `method`, у перегрузок одно имя и разные сигнатуры | все |
| varargs `int... xs` | блок `method`, параметр в сигнатуре | 03, 06 |
| Конструкторы, `super(...)`, `this(...)` | блок `constructor`; `super(...)`/`this(...)` — блок «Вызов» | `super(...)` — 01–04, 06; `this(...)` — нет в корпусе (`MethodFlowTest`) |
| Примитивы, обёртки, автоупаковка | код в блоке оператора | все |
| Массивы 1D | код в блоке оператора | 01–04, 06 |
| Массивы 2D | код в блоке оператора | 03 |
| Арифметика, логика, сравнение, приведение типов, тернарный оператор | код в блоке оператора | все (приведения — 03, 04, 06) |
| `if` / `else if` / `else` | `condition` с ветками Да/Нет | все (`else if` — 02, 04) |
| `switch` (классический, с провалом между `case`) | `switch` + `case`, провал — ребро к следующему `case` | 01, 03, 04 |
| `switch` со стрелками `case X ->` | `switch` + `case` без провала | 02, 03, 05, 06 |
| `for`, `for-each`, `while` | рамка `loop` (`loopKind`), возврат к заголовку и выход | все |
| `do-while` | рамка `loop`, тело выполняется до проверки | 03 |
| `while (true)` | `loop` с пометкой `infinite`, выход только через `break` | нет в корпусе (`MethodFlowTest`) |
| `break`, `continue`, `return` | свои блоки, рёбра к цели перехода | все |
| Метки циклов, `break outer` / `continue outer` | `jumpLabel` у цикла, ребро к нужному циклу | 03, 04 |
| `try` / `catch` / `finally` | рамка `try`, блоки `catch` и `finally` | `try`/`catch` — все; `finally` — 01, 03 |
| `throw` | блок `throw`, ребро `exception` с типом исключения | все |
| `Object`: `equals`, `hashCode`, `toString` | обычные методы | 01–04 |
| `String`, `StringBuilder`, `Character` | вызовы — код в блоке `call` | `String` — все; `StringBuilder` — 01–04, 06; `Character` — 04 |
| `Math` | код в блоке оператора | все |
| `System.exit` | блок `call` | 03 |

## 2. Консольный ввод-вывод

| Конструкция | На графе | В корпусе |
|---|---|---|
| `System.in` + `Scanner` | блок `call` / `variable` | все |
| `System.out`, `System.err` | блок `call` | все |
| `printf`, `String.format` | блок `call` | все |
| `Formatter` | блок `call` / `variable` | 02, 03, 04 |
| `StandardCharsets`, кириллица в выводе и входах | код в блоке; вывод сравнивается в UTF-8 | 03, 04 (кириллица — во всех) |

Песочница запускает программу с `stdin` из входа теста. В выводе нормализуются только адреса объектов (`@hex`), переводы
строк и пути песочницы (`OutputNormalizer`), остальное сравнивается дословно.

## 3. Коллекции `java.util`

| Конструкция | На графе | В корпусе |
|---|---|---|
| `List`, `ArrayList` | код в блоке оператора | все |
| `LinkedList` | код в блоке | 01, 02, 06 |
| `Set`, `HashSet`, `TreeSet` | код в блоке | `HashSet` — 02, 06; `TreeSet` — 01, 02, 04 |
| `Map`, `HashMap`, `TreeMap` | код в блоке | `HashMap` — 01–04; `TreeMap` — 01, 02, 04–06 |
| `Iterator`, свой `Iterable` | класс, реализующий `Iterable`, — рамка с методами; `Iterator` из анонимного класса — см. «Пробелы» | 02, 05 |
| `Collections.*`, `Arrays.*` | блок `call` | `Collections` — 01, 02, 04, 05; `Arrays` — 02–06 |
| `Comparator` (лямбдой, `comparing…`, анонимным классом) | код в блоке `call` | 01, 02, 05 |
| `Optional` | код в блоке | 02, 05 |
| `List.of` / `Set.of` / `Map.of` | код в блоке | 02 |

Правила анализа понимают коллекции: поиск в списке внутри цикла, `LinkedList.get(i)` в цикле, вложенный цикл по той же
коллекции. Авто-исправления меняют такой код только после зелёного quality gate.

## 4. Исключения

| Конструкция | На графе | В корпусе |
|---|---|---|
| Проверяемые исключения, `throws`, обязательный `catch` | `throws` — в сигнатуре метода; `catch` — блок в рамке `try` | 01–04, 06 |
| Непроверяемые (`RuntimeException` и наследники) | блок `throw` | все |
| Свои исключения через наследование | классы-рамки, конструкторы с `super(message)` | 01–04, 06 (непроверяемые — 01, 03, 04) |
| Multi-catch `catch (A \| B e)` | один блок `catch` со всеми типами | 03, 05, 06 |
| Цепочка причин (`new X(msg, cause)`, `getCause()`) | код в блоке | 01–04 |
| `try`-с-ресурсами | заголовок рамки `try` показывает ресурсы | нет в корпусе (`MethodFlowTest`) |

Исключение, вылетевшее из `main`, — тоже поведение. `/verify` сравнивает код выхода и `stderr` (тип, сообщение и
`Caused by`; кадры стектрейса отбрасываются, потому что меняются при любой правке строк).

## Пробелы: что видно хуже, чем остальное

Ни один из пробелов не мешает разбору, печати, выполнению и дифф-тестам: код сохраняется и проверяется как есть.
Страдает только визуализация. Пункты подтверждены прогоном ядра на отдельном примере и по коду
`DefaultGraphBuilder`/`MethodFlowBuilder`. Предложения для ядра — запрос роли 1 в Notion.

| Конструкция | Что происходит | Где в корпусе |
|---|---|---|
| Блок инициализации `static { … }` / `{ … }` | на обзоре его нет, блок-схему не открыть | 03, 05 |
| Компактный конструктор record `Student { … }` | на обзоре его нет: в JavaParser это не `ConstructorDeclaration` | 05 |
| Компоненты record `record P(int x, int y)` | отдельными полями не показаны, видны в коде рамки | 05 |
| Константы enum с телом `QUIZ(...) { double penalty() {…} }` | константы на обзоре не показаны; виден только абстрактный метод, реализации в константах не открываются | 05 |
| Методы анонимного класса `new Iterator<>() { … }` | весь класс — код одного блока (`variable`/`return`/`call`), его методы на обзоре не видны | 01, 02 |
| Тело лямбды с несколькими операторами | код внутри блока, без собственной блок-схемы | 02–06 |
| Локальный класс внутри метода | в блок-схеме — `raw`, на обзоре — отдельной рамкой верхнего уровня | нет |
| `synchronized`, локальный `record` | `raw` («Код как есть») | нет (вне scope) |
| Поле с несколькими переменными `int x, y;` | один блок, подпись по первой переменной, полный код в блоке | нет |

## Вне scope кейса

Многопоточность, рефлексия, файлы (`java.nio.file`), сеть, `java.time` не оцениваются. Код с ними разбирается и
показывается на графе, как любой другой. Но песочница запускает программу без сети, с файловой системой только
для чтения (запись — только во временный `/tmp`) и с лимитами времени и памяти. Поэтому такие программы могут
завершаться иначе, чем на машине разработчика.

## Как проверить самому

```bash
cd backend && mvn -B -pl core -am test -Dtest=CorpusRoundTripTest   # строки [corpus]: узлы, методы, raw, фаззинг
cd backend && mvn -B -pl analysis -am test -Dtest=CorpusAnalysisTest
cd backend && mvn -B -pl runner -am test -Dtest=CorpusSmokeTest
corpus/check.sh                                                     # то же вручную, со временем
```

В интерфейсе: «Импорт Java» → `corpus/<пример>/Main.java` → обзор → двойной клик по методу → «Проверить».
